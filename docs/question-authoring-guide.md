# 디지털 클론 질문 작성 가이드

## 1. 이 문서의 목적

이 문서는 디지털 클론을 만들기 위한 질문을 여러 사람이 일관된 기준으로 작성하도록 돕는 가이드다.

질문의 목적은 사용자를 성격 유형으로 분류하는 것이 아니라, 여러 상황에서 사용자가 실제로 무엇을 우선하고 어떤 조건에서 선택을 바꾸는지 수집하는 것이다.

질문 한 개를 실제로 작성할 때는 [질문 작성 템플릿](./notion-question-template.md)을 복제해 사용한다.

---

## 2. 좋은 질문이 수집해야 하는 것

좋은 질문은 최소한 하나의 실제 선택을 요구해야 한다.

```text
상황
  + 비교 가능한 4개 선택지
  + 선택에 사용되는 판단 기준
  = 사용자의 선택 경향을 보여주는 질문
```

질문 전체를 모았을 때 다음 정보를 알 수 있어야 한다.

- 무엇을 우선하는가
- 무엇과 무엇 사이에서 고민하는가
- 어떤 상황에서는 평소와 다르게 선택하는가
- 선택을 바꾸는 최소 조건은 무엇인가
- 같은 가치가 직업, 관계, 돈, 시간 등 여러 영역에서도 반복되는가

---

## 3. 질문 작성 기본 원칙

### 3.1 추상적인 성격 대신 구체적인 선택을 묻는다

피해야 할 질문:

```text
당신은 도전적인 사람인가요?
```

권장 질문:

```text
새로운 업무를 맡아야 한다면 무엇을 선택하나요?
```

```text
1. 이미 익숙해서 안정적으로 수행할 수 있는 업무
2. 어렵지만 새로운 기술을 배울 수 있는 업무
3. 업무 내용보다 보상이 높은 업무
4. 책임과 부담이 적어 여유를 확보할 수 있는 업무
```

사용자가 자신을 어떻게 평가하는지보다 실제 상황에서 무엇을 선택하는지가 더 중요하다.

### 3.2 한 질문에는 하나의 중심 상황을 둔다

질문 안에 서로 다른 상황을 동시에 넣지 않는다.

피해야 할 예:

```text
직장을 고르거나 친구와 여행할 때 안정성과 새로운 경험 중 무엇을 선택하나요?
```

직장과 여행은 별도 질문으로 나눈다. 같은 판단축이 서로 다른 영역에서 반복되는지는 질문 간 관계를 통해 확인한다.

### 3.3 정답처럼 보이는 선택지를 만들지 않는다

다음 표현은 특정 선택지를 도덕적으로 우월하거나 열등하게 보이게 할 수 있다.

```text
책임감 있게 가족을 돕는다.
나만 생각하고 개인 시간을 보낸다.
```

중립적인 표현을 사용한다.

```text
가족이 요청한 일을 우선한다.
이미 계획한 개인 일정을 우선한다.
```

### 3.4 필요한 정보는 질문 안에 제공한다

답변자가 서로 다른 상황을 상상하지 않도록 핵심 전제를 명확히 한다.

```text
두 회사의 출퇴근 시간과 복지는 동일하다고 가정합니다.
```

모든 조건을 완벽하게 통제할 필요는 없다. 선택에 직접 영향을 주는 조건만 적는다.

### 3.5 선택 이유를 질문 문장에 미리 넣지 않는다

피해야 할 예:

```text
성장하기 위해 어려운 프로젝트를 선택하시겠어요?
```

권장 표현:

```text
새로운 업무를 선택해야 한다면 무엇을 고르나요?
```

선택 이유는 사용자가 별도로 작성하거나 선택지 의도에서 내부적으로 관리한다.

## 4. 네 개 선택지를 만드는 방법

선택지는 반드시 4개로 고정한다.

좋은 선택지 네 개는 같은 질문에 답하면서 서로 다른 우선순위를 나타내야 한다.

```text
선택지 1: 핵심 판단축의 한쪽
선택지 2: 핵심 판단축의 반대쪽
선택지 3: 현실적인 제3의 우선순위
선택지 4: 또 다른 현실적 우선순위 또는 부담 회피
```

예시:

```text
질문: 새로운 업무를 선택해야 한다면 무엇을 가장 우선하나요?

1. 익숙함과 안정성
2. 학습과 성장
3. 금전적 보상
4. 시간과 여유
```

### 선택지 작성 규칙

- 네 선택지는 같은 수준의 구체성을 가진다.
- 특정 선택지만 지나치게 길게 설명하지 않는다.
- 한 선택지 안에 서로 다른 장점을 여러 개 묶지 않는다.
- `모두`, `아무거나`, `상황에 따라 다름`을 기본 선택지로 넣지 않는다.
- 의미가 거의 같은 선택지를 표현만 바꿔 반복하지 않는다.
- 극단적이거나 비현실적인 선택지로 숫자만 채우지 않는다.
- 선택지 간 장단점이 어느 정도 균형을 이루게 한다.

피해야 할 예:

```text
1. 안정적인 회사
2. 안정적이고 연봉도 높으며 복지도 좋은 회사
3. 위험한 회사
4. 잘 모르겠다
```

두 번째 선택지가 지나치게 유리하고 세 번째 선택지는 부정적으로 표현되어 비교가 무너진다.

## 5. 질문 의도 작성법

질문 의도는 사용자에게 보여주는 설명이 아니라 내부 전처리와 검수를 위한 정보다.

다음 두 가지를 1~2문장으로 작성한다.

1. 어떤 상황의 선택을 묻는가
2. 어떤 우선순위를 구분하려는가

예시:

```text
새로운 업무를 선택할 때 숙련도, 성장 기회, 금전적 보상, 개인적 여유 중 어떤 기준을 우선하는지 확인한다.
```

피해야 할 의도:

```text
사용자가 야망 있는 사람인지 확인한다.
```

질문 의도에서도 사람의 성격을 단정하지 않고 관찰하려는 선택 기준을 적는다.

## 6. 판단축 작성법

판단축은 임베딩 검색과 Jev 관계 평가가 질문 간 공통 고민을 찾는 데 도움을 준다.

```text
핵심: 안정성과 익숙함 ↔ 도전과 성장
보조: 금전적 보상 ↔ 시간과 심리적 여유
```

### 판단축 규칙

- 핵심 판단축은 반드시 하나 작성한다.
- 보조 판단축은 실제 선택지에 존재할 때만 작성한다.
- `좋음 ↔ 나쁨`처럼 가치 판단이 포함된 표현은 피한다.
- 너무 넓은 단어보다 선택을 구분할 수 있는 표현을 쓴다.

너무 넓은 예:

```text
핵심: 가치관 ↔ 현실
```

권장 예:

```text
핵심: 장기 성장 가능성 ↔ 단기적인 안정성
```

## 7. 선택지 의도 작성법

선택지 의도는 각 선택지가 해당 질문 안에서 어떤 판단 방향을 나타내는지 설명한다.

```text
1. 불확실성을 줄이고 현재의 숙련도와 안정성을 우선하는 선택
2. 당장의 어려움을 감수하고 학습과 장기 성장을 우선하는 선택
3. 업무 경험보다 직접적인 금전적 보상을 우선하는 선택
4. 성장이나 보상보다 부담 감소와 개인적 여유를 우선하는 선택
```

### 선택지 의도 규칙

- 질문 안에서 확인할 수 있는 의미만 적는다.
- 사용자가 왜 골랐는지 미리 단정하지 않는다.
- 성격, 능력, 도덕성, 정신 상태를 추론하지 않는다.
- 네 선택지의 의도를 같은 수준으로 설명한다.

피해야 할 예:

```text
2. 야망이 많고 성공 욕구가 강한 사람의 선택
```

권장 예:

```text
2. 현재의 편안함보다 학습과 성장 가능성을 우선하는 선택
```

---

## 8. 상황 및 전제 작성법

상황 및 전제는 답변자가 서로 다른 숨은 조건을 상상할 가능성이 있을 때만 작성한다.

필요한 예:

```text
두 회사의 근무 시간, 출퇴근 거리, 복지는 동일하고 연봉과 성장 기회만 다르다고 가정한다.
```

필요하지 않은 경우:

```text
없음
```

전제가 너무 많으면 질문이 시험 문제처럼 되므로 선택에 직접 필요한 내용만 유지한다.

---

## 9. 검색 태그 작성법

검색 태그는 질문 분포 확인, 중복 검토, 검색 보조에 사용한다.

```text
직업, 업무 선택, 성장, 안정성, 보상, 여유
```

### 태그 규칙

- 쉼표로 구분한다.
- 3~7개 정도로 작성한다.
- 너무 구체적인 문장 대신 반복 사용 가능한 단어를 쓴다.
- 질문 영역과 주요 판단 기준을 함께 넣는다.

```text
영역 태그: 직업, 관계, 가족, 재정, 생활, 학습
판단 태그: 성장, 안정성, 자율성, 보상, 시간, 위험
```

## 10. 질문 간 구성 원칙

질문 100개를 만들 때는 서로 다른 문장 100개보다 서로 다른 판단 상황 100개를 만드는 것이 중요하다.

### 10.1 동일한 판단축을 여러 영역에서 확인한다

예를 들어 `안정성 ↔ 도전`은 다음처럼 여러 영역에서 확인할 수 있다.

```text
직업: 익숙한 업무와 새로운 프로젝트
재정: 예금과 변동성 높은 투자
생활: 익숙한 지역과 새로운 도시
관계: 기존 관계 유지와 새로운 만남
학습: 잘하는 분야 심화와 낯선 분야 학습
```

같은 질문을 표현만 바꿔 반복하는 것이 아니라, 판단 경향이 다른 상황에서도 유지되는지 확인한다.

### 10.2 한 영역에 질문이 몰리지 않게 한다

100개 묶음을 만들기 전에 영역별 목표 개수를 정한다.

예시:

| 영역 | 목표 개수 |
|---|---:|
| 직업과 성장 | 15 |
| 돈과 소비 | 15 |
| 시간과 생활 방식 | 15 |
| 가족과 관계 | 15 |
| 위험과 불확실성 | 10 |
| 학습과 창작 | 10 |
| 책임과 공동체 | 10 |
| 변화와 환경 | 10 |

이 숫자는 시작점이며 최종 질문 목적에 맞게 조정한다.

### 10.3 선택지 위치를 섞는다

`성장` 관련 선택지가 항상 2번이면 사용자가 번호 패턴으로 답할 가능성이 있다.

질문 전체에서 특정 판단 방향이 같은 번호에 반복되지 않도록 선택지 순서를 섞는다.

### 10.4 비슷한 질문은 실제 차이를 설명할 수 있어야 한다

두 질문이 비슷해 보여도 다음 중 하나가 다르면 유지할 수 있다.

- 적용되는 생활 영역
- 선택의 시간 범위
- 위험의 크기
- 되돌릴 수 있는지 여부
- 타인에게 미치는 영향
- 금전적 또는 시간적 제약

차이를 설명할 수 없다면 하나를 제거한다.

## 11. 작성 순서

질문 하나는 다음 순서로 작성한다.

```text
1. 확인할 판단축을 정한다.
2. 판단이 드러날 구체적인 상황을 정한다.
3. 서로 다른 우선순위를 나타내는 선택지 4개를 만든다.
4. 질문 문장을 중립적으로 다듬는다.
5. 질문 의도와 선택지 의도를 작성한다.
6. 필요한 상황 및 전제를 추가한다.
7. 검색 태그를 작성한다.
8. 다른 질문과 중복되는지 확인한다.
9. 선택지 길이와 매력도가 균형적인지 검토한다.
```

100개를 작성할 때는 질문 하나를 완성한 뒤 다음으로 넘어가기보다 다음처럼 묶어서 작업해도 된다.

```text
판단축 20개 선정
  → 각 판단축의 상황 후보 작성
  → 질문 문장 작성
  → 선택지 작성
  → 의도·태그 작성
  → 전체 중복 검수
```

## 12. 최종 체크리스트

### 질문

- [ ] 실제 선택 상황인가?
- [ ] 질문 하나에 중심 상황이 하나뿐인가?
- [ ] 답을 유도하거나 도덕적으로 평가하는 표현이 없는가?
- [ ] 사용자가 이해할 수 있는 구체적인 문장인가?

### 선택지

- [ ] 선택지가 정확히 4개인가?
- [ ] 네 선택지가 같은 질문에 답하고 있는가?
- [ ] 의미가 중복되는 선택지가 없는가?
- [ ] 비현실적이거나 명백히 열등한 선택지가 없는가?
- [ ] 한 선택지만 지나치게 길거나 유리하지 않은가?

### 내부 설명

- [ ] 질문 의도가 선택 기준을 설명하는가?
- [ ] 핵심 판단축이 명확한가?
- [ ] 선택지 의도가 사용자의 성격을 단정하지 않는가?
- [ ] 필요한 전제가 빠지지 않았는가?
- [ ] 검색 태그가 다른 질문과 재사용 가능한가?

### 질문 간 검토

- [ ] 기존 질문과 표현만 다른 중복 질문이 아닌가?
- [ ] 같은 판단축을 다른 상황에서 측정할 가치가 있는가?
- [ ] 특정 생활 영역에 질문이 과도하게 몰리지 않았는가?
- [ ] 특정 판단 방향이 같은 선택지 번호에 반복되지 않는가?

## 13. 작성 템플릿

각 질문은 반드시 [질문 작성 템플릿](./notion-question-template.md)의 고정 필드와 코드 블록 형식을 사용한다.

```text
질문
선택지
질문 의도
판단축
선택지 의도
상황 및 전제
검색 태그
작성 메모
```
